`outbound-sdk/tools/claude-agent` gives the [tools](/docs/tools) to the Claude Agent SDK as an in-process MCP server. Nothing is spawned and no port is opened: the server lives in your process.

This subpath imports `@anthropic-ai/claude-agent-sdk`, which is an optional peer dependency. Install it only if you import this subpath. See [installation](/docs/installation).

| Export | What it returns |
| --- | --- |
| `claudeAgentTools(outbound, options)` | `server` to pass as `options.mcpServers[serverName]`, `allowedTools` to pass as `options.allowedTools`, and `serverName`. |
| `claudeToolDefinitions(outbound, options)` | The tool definitions on their own, for an MCP server you build yourself with `createSdkMcpServer`. |

Both take the `only` and `extra` options of [`createTools`](/docs/tools#options). `claudeAgentTools` also takes `serverName`, which defaults to `outbound`. The agent addresses each tool as `mcp__<serverName>__<tool>`.

- **Every tool is marked `readOnlyHint: true`.** All of them only read, which is why `allowedTools` lists every one: you can pre-approve the whole set.
- **A result is MCP text content.** The tool's result object is serialized as JSON in one `text` item.
- **A failed tool sets `isError: true`.** The content is still the `{ ok: false, error, next }` object, so the model can read why.

  The test suite loads `query.ts`, type-checks it against the Agent SDK and
  never calls `ask`, so the agent loop is wiring that was not run. The first

  performs when Claude asks for the tool.

To serve the same tools to Claude Code, Claude Desktop or another MCP client without writing code, run [`outbound mcp`](/docs/cli/mcp).

## Reply text

A model given `reply_samples` can ask for reply text. It comes back truncated and marked as untrusted. See [untrusted content](/docs/tools/untrusted-content).
