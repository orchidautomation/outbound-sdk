`aiSdkTools(outbound)` from `outbound-sdk/tools/ai-sdk` returns the [tools](/docs/tools) as one AI SDK tool per outbound tool, keyed by tool name. Pass the object as `tools` to `generateText` or `streamText`.

This subpath imports `ai`, which is an optional peer dependency: version 6 or 7. Install it only if you import this subpath. See [installation](/docs/installation).

`aiSdkTools` takes the same `only` and `extra` options as [`createTools`](/docs/tools#options).

Each tool has a `description`, an `inputSchema` built from the tool's JSON Schema, and an `execute` function that returns the tool's result object. A failed tool returns `{ ok: false }` from `execute`. It does not throw, so the AI SDK passes the failure to the model as an ordinary tool result.

## Wiring it to a model

<include meta='title="generate.ts"'>
  ../../_examples/tools-ai-sdk/generate.ts
</include>

`ask` takes the instance, a model and a question. `stopWhen: stepCountIs(5)` gives the model up to five steps, so it can call a tool, read the result and answer inside one `generateText` call.

The first live run found a problem that is now fixed. The model does not know today's date, so it asked for 2024 to 2026 and found no data. Every tool result now carries `meta.today`, and the date inputs tell the model to leave the range out for the whole history and not to guess.

## Reply text

A model given `reply_samples` can ask for reply text. It comes back truncated and marked as untrusted. See [untrusted content](/docs/tools/untrusted-content).
