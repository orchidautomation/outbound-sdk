`openaiTools(outbound)` from `outbound-sdk/tools` returns the [tools](/docs/tools) in the shape the OpenAI SDK takes. It is built without importing `openai`, so it adds no dependency, and it works with any client that accepts the same function-tool shape.

It returns three things:

| Property | What it is |
| --- | --- |
| `tools` | Function tools for the Responses API: `type`, `name`, `description`, `parameters`, `strict`. Pass as `tools` to `client.responses.create`. |
| `chatTools` | The same tools for Chat Completions, each nested under `function`. Pass as `tools` to `client.chat.completions.create`. |
| `handle(name, argumentsJson)` | Runs one function call. Takes the call's `name` and its `arguments` string, returns the result as a JSON string. |

`openaiTools` takes the same `only` and `extra` options as [`createTools`](/docs/tools#options).

- **`strict` is `false`.** The schemas have optional fields, which OpenAI's strict mode does not accept. The tool validates the arguments itself and reports anything wrong as a result.
- **An empty `arguments` string means no arguments.** `handle` reads it as `{}`.
- **`handle` never throws.** An unknown tool name and arguments that are not JSON come back as `{ ok: false }` with the code `Invalid`.

## Wiring it to a model

The loop around these pieces is yours:

1. Call `client.responses.create` with your model, your input and `tools`.
2. For each `function_call` item in the output, call `handle(item.name, item.arguments)`.
3. Append a `function_call_output` item with the same `call_id` and the returned string, and call the API again.
4. Stop when a response has no function calls.

With Chat Completions, pass `chatTools`, read `message.tool_calls`, and answer each with a `tool` message whose content is the string `handle` returned.

## Reply text

A model given `reply_samples` can ask for reply text. It comes back truncated and marked as untrusted. See [untrusted content](/docs/tools/untrusted-content).
