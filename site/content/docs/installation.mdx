```sh
npm install outbound-sdk
```

The package is on npm as [outbound-sdk](https://www.npmjs.com/package/outbound-sdk); its versions are listed in the [changelog](https://github.com/orchidautomation/outbound-sdk/blob/main/packages/outbound-sdk/CHANGELOG.md). Releases from 0.2.0 on are published by the repository's publish workflow with an npm provenance attestation, which ties the package to the commit it was built from. 0.1.0, the first, was published from a maintainer's machine, so it carries none; its tarball is also attached to the [v0.1.0 GitHub release](https://github.com/orchidautomation/outbound-sdk/releases/tag/v0.1.0).

On 2026-11-15 `npm install outbound-sdk` installed 0.2.0 into an empty project, the sample on the [introduction](/docs) ran from it, and from an empty folder `npx -y outbound-sdk providers` and `npx -y outbound-sdk mcp` answered.

## From the repository

The repository is public at [github.com/orchidautomation/outbound-sdk](https://github.com/orchidautomation/outbound-sdk). To run an unreleased commit, build the package, pack it, and install the tarball in your project. The repository needs Node 24.15 or later to build; the built package runs on Node 22.

```sh
git clone https://github.com/orchidautomation/outbound-sdk.git
cd outbound-sdk
npm ci
npm run build
cd packages/outbound-sdk && npm pack   # writes outbound-sdk-<version>.tgz

# in your project
npm install /path/to/outbound-sdk-<version>.tgz
```

## What it needs

- **Runtime:** Node 22 or later, Bun, or any runtime with `fetch`. The built package is loaded on Node 22 and on Bun in CI. No CI job runs it on Cloudflare Workers yet.
- **Modules:** ESM only. From a CommonJS file, use a dynamic `import()`.
- **Dependencies:** `zod` is the only one.
- **Optional peers:** `ai` (version 6 or 7) for `outbound-sdk/tools/ai-sdk`, and `@anthropic-ai/claude-agent-sdk` for `outbound-sdk/tools/claude-agent`. Install them only if you import those subpaths.
- **Types:** included. There is no `@types` package.

## Subpaths

Each adapter and plugin is its own subpath, so what you do not import is not bundled.

| Import | Holds |
| --- | --- |
| `outbound-sdk` | `createOutbound`, the types, `OutboundError` |
| `outbound-sdk/instantly`, `/smartlead`, `/heyreach` | One [adapter](/docs/adapters) each |
| `outbound-sdk/memory` | The [in-memory adapter](/docs/adapters/memory), for tests and demos |
| `outbound-sdk/combine` | [Several adapters behind one instance](/docs/adapters/combine) |
| `outbound-sdk/insights` | The 26 [insights](/docs/insights) |
| `outbound-sdk/<plugin>` | One [plugin](/docs/plugins) each |
| `outbound-sdk/redis` | A [rate budget shared between processes](/docs/rate-limits) |
| `outbound-sdk/tools`, `/tools/ai-sdk`, `/tools/claude-agent` | [AI tools](/docs/tools) |
| `outbound-sdk/cli` | The [CLI](/docs/cli) and [MCP server](/docs/cli/mcp), as functions |
| `outbound-sdk/webhooks` | [Webhook](/docs/webhooks) parsing and verification |
| `outbound-sdk/providers`, `/loader` | The provider catalog, and an adapter chosen from the environment |

## Keys

Each adapter reads its key from the environment, or takes it as `apiKey`.

| Adapter | Variable | Notes |
| --- | --- | --- |
| Instantly | `INSTANTLY_API_KEY` | An API V2 key. The `all:read` scope is enough. |
| Smartlead | `SMARTLEAD_API_KEY` | Sent as a query parameter, as Smartlead requires. It is removed from every error and log line. |
| HeyReach | `HEYREACH_API_KEY` | A workspace API key. |

A read-only key is the right key to give it. No method of the SDK writes, and a key that cannot write makes that true of the credential too.
