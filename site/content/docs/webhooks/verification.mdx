An endpoint that accepts webhooks is a public URL. Without a check, anyone who finds it can post events to it. `parse` checks a request when you pass `secret`, in one of two ways depending on the vendor.

| Vendor | `events.verify` | What `secret` is | What is checked |
| --- | --- | --- | --- |
| Instantly | `secret` | A value you choose | The request carries that value in its URL or a header |
| HeyReach | `secret` | A value you choose | The request carries that value in its URL or a header |
| Smartlead | `signature` | The webhook's `whsec_` signing secret from Smartlead | A Standard Webhooks signature over the body, and a timestamp no more than five minutes off |

`events.verify` is the adapter's [capability](/docs/capabilities) that says which one applies:

<Callout type="warning" title="No secret, no check">
  When the `secret` option is `undefined`, `parse` checks nothing and parses
  whatever it is given. An environment variable that is not set is `undefined`.
  Read the secret once at start-up and refuse to run without it, as the handler
  on the [overview](/docs/webhooks#a-route-handler) does.
</Callout>

Verification is tested on requests the test suite builds itself. No check has been run on a live delivery from a vendor. See [what is verified](/docs/status).

## A shared secret: Instantly and HeyReach

Neither vendor signs its payloads. You choose a long random value, put it where the vendor will send it back with every delivery, and pass the same value as `secret`. `parse` looks for it in:

- any segment of the URL path, for example `https://your.app/hooks/<secret>`
- the query parameters `secret`, `token` or `key`
- the headers `x-webhook-secret` or `x-outbound-secret`
- an `Authorization: Bearer <secret>` header

A shared secret proves the sender knows the secret. It does not prove the body was not changed on the way, and a captured request can be sent again. Use HTTPS, and prefer a header to the URL where the vendor lets you set one, because URLs are commonly written to access logs.

### A secret in the URL path

For a vendor that does not sign, the simplest place for the secret is a segment of the webhook URL. Generate it once with a cryptographic random source, keep it with your other secrets, and register `https://your.app/hooks/<vendor>/<secret>` with the vendor. On each delivery, compare the segment to the stored value in constant time with `timingSafeEqual` from `outbound-sdk/webhooks`, never with `===`, which stops at the first different character and so tells a guesser how much was right. `parse` with `secret` does this comparison for you.

To rotate the secret, register a second URL with the new one, accept both for a while, then delete the old webhook. Smartlead is different: it signs each delivery with a `whsec_` secret that an admin supplies when turning signing on, so there you check the signature, as below, and need no secret in the URL.

## A signature: Smartlead

Smartlead can sign a webhook following the Standard Webhooks specification. Signing is off until you turn it on for the webhook in Smartlead. Pass the webhook's `whsec_` secret as `secret`. `parse` then requires:

- the headers `webhook-id`, `webhook-timestamp` and `webhook-signature`
- a timestamp within five minutes of now, in either direction
- a `v1` signature equal to the HMAC-SHA256 of `<id>.<timestamp>.<body>` under the secret. Several signatures may be sent, separated by spaces; one match is enough.

The sample signs Smartlead's documented payload itself, with a made-up secret, the way the specification describes.

With `provider: "smartlead"` and a `secret`, an unsigned Smartlead webhook always fails, and so does a shared secret in the URL: only the signature is accepted. If you cannot turn signing on, there is no check for Smartlead through `parse` with the provider named.

The signature covers the exact bytes of the body, which `parse` reads from the `Request` itself. Pass it the original request, not one rebuilt from parsed JSON.

## When the check fails

`parse` throws an `OutboundError` with the code `Unauthorized` and the provider:

| Vendor check  | Message                                        |
| ------------- | ---------------------------------------------- |
| Shared secret | `The webhook does not carry the shared secret` |
| Signature     | `The webhook signature does not match`         |

Answer with a 401 and do not process the body. `Unauthorized` is the same code a rejected API key uses; see [errors](/docs/api/errors).

## verify

`verify(request, { provider, secret })` runs the same check and resolves to `true` or `false`. It does not throw for a failed check, and it reads a copy of the request, so you can still pass the request to `parse` afterwards. It does throw `Invalid` for a provider that has no parser. `secret` is required.

## With provider auto

With `provider: "auto"`, the kind of check follows the vendor detected from the body: a body that looks like Smartlead's is checked by signature, and any other body, including one no parser recognises, is checked for the shared secret. Naming the provider removes that dependence on the body's shape.

- `timingSafeEqual(left, right)` compares two strings without stopping at the first difference, so the time it takes does not reveal how much of a guess was right. Use it for any secret comparison of your own.
