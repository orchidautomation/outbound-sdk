The package ships one binary, `outbound`. It is a thin shell over the SDK: each command makes the same read you would make in code and prints the result as JSON. It adds no behaviour of its own, and like the SDK it only reads.

<Callout type="warning" title="Not on npm yet">
  `outbound-sdk` is not published, so `npx outbound-sdk` does not work today.
  The binary is available after you install the package from a tarball built in
  the repository. See [installation](/docs/installation).
</Callout>

## How the samples run the CLI

Every command shown in this section went through `run`, the function the `outbound` executable calls, exported from `outbound-sdk/cli`. The helper below runs it in the test process with the provider set to `memory`, prints a `$ outbound ...` line, then what the CLI wrote. The executable itself, as a separate process, is covered by the SDK's own tests and is not what these samples start.

<include meta='title="cli.ts"'>../../_examples/cli-commands/cli.ts</include>

`run(argv, io)` takes the arguments after `outbound` and an object with `stdout` and `stderr` functions, and resolves to the exit code. You can call it the same way to embed the CLI in a script. `io.stdin` supplies lines for `outbound mcp`, and `io.adapter` replaces the adapter the environment would choose, which is meant for tests.

## Choosing the provider

A command that reads data needs an adapter. The CLI builds one from the environment:

1. `--provider <id>` if given, otherwise the `OUTBOUND_SDK_PROVIDER` environment variable.
2. The id is one of `instantly`, `smartlead`, `heyreach` or `memory`.
3. The adapter reads its own key from the environment: `INSTANTLY_API_KEY`, `SMARTLEAD_API_KEY` or `HEYREACH_API_KEY`. `outbound providers` lists the variables each one reads.

4. The id `all` builds every provider whose key is set, with no list to maintain: one key gives that provider alone, several give one [combined](/docs/adapters/combine) instance. Set another key and its tool is included the next time the command starts. `memory` is never part of `all`, and with no key set the command exits with code 1 and names the variables.

`memory` needs no key. It runs on a small built-in demo data set, the same one behind `demoData()` in `outbound-sdk/memory`: two campaigns, three leads, a few messages. Use it to try a command before pointing the CLI at a real account.

```sh
# a real account
export OUTBOUND_SDK_PROVIDER=instantly
export INSTANTLY_API_KEY=...
outbound campaigns --status active

# the demo data, for one command
outbound campaigns --provider memory
```

Those shell lines are not run by the test suite. The CLI takes no key on the command line.

## Plugins

A command runs on one adapter and, by default, no [plugins](/docs/plugins). `outbound mcp` is the exception: it runs with [`redact()`](/docs/plugins/redact) unless given `--no-redact`, because what it returns goes to a model. Any command takes these options:

| Option | Adds |
| --- | --- |
| `--redact` | `redact()`: masks personal fields. On by default for `outbound mcp` only. |
| `--no-redact` | Turns the default `redact()` off for `outbound mcp`. |
| `--cache <seconds>` | `cache()` with that time to live. |
| `--max-requests <n>` | `budget({ maxRequests: n, per: "run" })`. A command is one run; on the MCP server each tool call is one. |
| `--config <file>` | The plugins a file lists as `export default defineConfig({ plugins: [...] })`. |

[The MCP server page](/docs/cli/mcp#plugins) has a run of each, the order the plugins are placed in, and what a config file may hold. How far each real adapter has been checked is on [what is verified](/docs/status).

`help` and `providers` need no adapter and work with nothing set.

## Output

A command prints one JSON value on standard output: indented by default, on one line with `--compact`. Records are the SDK's [records](/docs/api/records), with `meta` on a single read. List commands print a plain array and stop at `--limit`, which defaults to 50.

## Exit codes and errors

| Exit code | When |
| --- | --- |
| `0` | The command ran and got its answer. |
| `1` | Anything else: an unknown command or option, a missing argument, a flag value that is not one of the allowed words, a record that does not exist, a read the adapter cannot serve, a rejected key, or a tool whose result is `{ "ok": false }`. |

On failure nothing is written to standard output, with one exception: `outbound tool` prints the tool's `{ "ok": false }` result there and writes nothing to standard error. Standard error gets `<code>: <message>`, where the code is an [`OutboundError` code](/docs/api/errors) such as `Invalid`, `NotFound`, `Unsupported` or `Unauthorized`, or `Error` for a failure that is not an `OutboundError`.
