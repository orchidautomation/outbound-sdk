Every block on this page is the output of the CLI's own code, run on the in-memory adapter's demo data by the test suite. [The overview](/docs/cli#how-the-samples-run-the-cli) shows the helper that runs it. A line starting with `$` is the command. A line `(exit code 1)` is added by the helper, and a line in square brackets stands in for output too long to print.

The output shows what the CLI does with the demo data. It does not show what a vendor returns. See [what is verified](/docs/status).

## All commands

| Command | Reads | SDK call |
| --- | --- | --- |
| `providers` | The adapters the CLI can load. Needs no adapter. | the provider catalog |
| `capabilities` | What the chosen adapter can do, its maturity and caveats | `outbound.capabilities`, `maturity`, `caveats` |
| `campaigns` | Campaigns | `outbound.campaigns.listAll` |
| `campaign <id>` | One campaign, or with a flag its stats, sequence, subsequences or settings | `outbound.campaign(id)` |
| `senders` | Mailboxes and LinkedIn seats | `outbound.senders.listAll` |
| `health <sender id>` | One sender's DNS, sign-in and warmup state | `outbound.sender(id).health` |
| `leads` | Leads, across the account or in one campaign or list | `outbound.leads.listAll` |
| `lists` | Saved lead lists | `outbound.lists.listAll` |
| `replies` | Replies from prospects | `outbound.replies.listAll` |
| `thread <id>` | The messages in one conversation | `outbound.thread(id).messages` |
| `stats` | Workspace totals, or one row per day | `outbound.stats` |
| `tags` | Tags | `outbound.tags.listAll` |
| `blocklist` | Blocked addresses and domains | `outbound.blocklist.listAll` |
| `webhooks` | Webhook subscriptions registered at the vendor | `outbound.webhooks.listAll` |
| `limits` | The current rate budget | `outbound.limits` |
| `tools` | The [AI tools](/docs/tools) the instance can serve, then the [insights](/docs/insights), as `outbound mcp` lists them | `createTools` with `insightTools` |
| `tool <name>` | Runs one of them | `tool.call` |
| `insight [name]` | Lists the [insights](/docs/insights), or runs one | `listInsights`, `runInsightByName` |
| `person <email or URL>` | Every campaign one person is in, across every tool | `runInsightByName("person_summary")` |
| `native [name]` | Lists the vendor's [own reads](/docs/native), or runs one | `outbound.native` |
| `mcp` | Starts the [MCP server](/docs/cli/mcp) on stdio | `createMcpServer` |
| `help` | The usage text. Also `--help`, `-h`, or no command. |  |
| `version` | The installed version. Also `--version` or `-v`. Needs no adapter. | the package's `package.json` |
| `update` | Whether npm has a newer version, and how to get it. Needs no adapter. | `npm view outbound-sdk version` |

## Flags

| Flag | Commands | Meaning |
| --- | --- | --- |
| `--provider <id>` | all that need an adapter | The adapter to use, or `all` for every provider whose key is set. Overrides `OUTBOUND_SDK_PROVIDER`. |
| `--compact` | all that print JSON | Print the JSON on one line. |
| `--raw` | all that print JSON | Keep each record's `raw`, the vendor's own payload. Left out by default: for a reply it can hold the whole quoted thread, `--bodies` or not. |
| `--help`, `-h` | all | Print the usage text and exit 0. After a command, `outbound leads --help`, print that command's options and the ones every command takes. |
| `--limit <n>` | `campaigns`, `senders`, `leads`, `lists`, `replies`, `tags`, `blocklist`, `webhooks`, `person` | Stop after this many records. A positive whole number. Defaults to 50. When a listing stops there and more records exist, standard error says so, for example "Stopped at 50 leads; more exist. Pass --limit to read more." Standard output is the same JSON either way. |
| `--status <status>` | `campaigns` | Only campaigns with this status: `active`, `paused`, `draft`, `completed`, `archived` or `unknown`. |
| `--stats` | `campaign` | The campaign's counts. |
| `--sequence` | `campaign` | The campaign's steps and variants. |
| `--subsequences` | `campaign` | The campaign's subsequences. |
| `--settings` | `campaign` | How the campaign is set up to send. |
| `--from <day>`, `--to <day>` | `campaign --stats`, `stats` | First and last day, `YYYY-MM-DD`. |
| `--by day\|total` | `campaign --stats`, `stats` | `day` gives one row per day. `total`, the default, gives one total row. Any other value is refused as `Invalid`. |
| `--campaign <id>` | `leads`, `replies`, `webhooks` | Only records for this campaign. |
| `--list <id>` | `leads` | Only leads in this saved list. |
| `--category <category>` | `replies` | Only replies in this category: `positive`, `negative`, `neutral`, `ooo`, `bounce`, `unsubscribe` or `unknown`. |
| `--since <ISO date>` | `replies` | Only replies on or after this time. |
| `--bodies` | `replies`, `thread` | Include message text. Left out by default. |
| `--input <json>` | `tool`, `insight`, `native` | The input, as a JSON object in one argument. Defaults to `{}`. |
| `--card`, `--slack` | `tool`, `insight`, `person` | Print the answer as a [card](/docs/cards), or as a Slack message. |
| `--redact`, `--no-redact` | all that need an adapter | Mask personal fields, or do not. Masking is on by default for `mcp` only. |
| `--cache <seconds>` | all that need an adapter | Reuse an answer for this long. |
| `--max-requests <n>` | all that need an adapter | The most vendor requests one command, or one MCP tool call, may make. |
| `--config <file>` | all that need an adapter | Load plugins from a file. |

The last five add [plugins](/docs/cli#plugins); the overview says which plugin each adds and in what order.

A flag a command does not take is refused before any request, with exit code 1: `outbound leads --since 2030-01-01` writes "Invalid: --since is not an option of leads". The flags in the last five rows, `--provider`, `--compact`, `--raw` and `--help` are taken by every command.

When `campaign` gets one of `--stats`, `--sequence`, `--subsequences` and `--settings`, it prints that answer. Given two or more, it prints one object with each answer under its name: `outbound campaign <id> --stats --sequence` prints `{ "sequence": ..., "stats": ... }`.

## tools, tool and insight

`tools` lists the [AI tools](/docs/tools) and the insights, as `outbound mcp` serves them, and `tool` runs any of them with the same input a model would send. `insight` with no name lists the 26 insights with their input schemas, and with a name runs one.

<include lang="text" meta='title="Output"'>
  ../../_examples/cli-commands/agent.out.txt
</include>

Both commands exit 1 on failure, and say why in different places. A tool never throws, so `outbound tool` prints the tool's `{ "ok": false }` result on standard output, where a script can read `error` and `next`. An insight throws, so `outbound insight` writes the reason to standard error and prints nothing on standard output.

`tools` lists `cross_channel_lead` because the CLI always installs the [identity](/docs/plugins/identity) plugin, and leaves it out with `--redact`, which masks the identifiers it matches on. It lists `compare_clients` only with the [clients](/docs/plugins/clients) plugin, from a file passed to [`--config`](/docs/cli#plugins). The insights are listed after the built-in tools, as `outbound mcp` serves them.

## person

`person` takes an email address or a LinkedIn profile URL and prints the `person_summary` insight: every campaign that person is in, in every tool the CLI reads. With several vendor keys set and no provider named, that is every one of them, so one command finds a person on Instantly and on HeyReach. `--card` and `--slack` print it as a [card](/docs/cards), as `tool` and `insight` do.

## native

`native` with no name prints the adapter's catalog of [native reads](/docs/native), which costs no request. With a name it runs that read and prints the vendor's own response. The in-memory adapter has no vendor behind it, so its catalog is empty and any read is refused.

## version and update

`outbound version` prints the installed version and nothing else, so a script can read it. `outbound --version` and `outbound -v` do the same.

`outbound update` asks npm for the newest published version, through the `npm` on your `PATH`. If you already have it, the command says so and changes nothing. Otherwise what it does depends on how the package was installed:

- **Global install** (`npm install --global outbound-sdk`): it runs `npm install --global outbound-sdk@latest`.
- **Installed in a project**: it prints `npm install outbound-sdk@latest` for you to run. It does not run it, because that would rewrite the project's `package.json` and lockfile.
- **Run through npx**: it prints `npx outbound-sdk@latest <command>`, since npx keeps its own copy.

If npm cannot be reached, the command exits with code 1 and prints npm's error.

## mcp

`outbound mcp` does not print a result and exit. It reads JSON-RPC messages from standard input until it closes. See [`outbound mcp`](/docs/cli/mcp).
