Every adapter maps its vendor's data onto the same records. A `Campaign` from Instantly and a `Campaign` from HeyReach have the same fields with the same meaning. Each record type is exported from `outbound-sdk` as a TypeScript type, and most have an exported Zod schema.

Which fields a vendor can fill is an adapter fact: see the [adapter pages](/docs/adapters). A field a vendor cannot fill is `null`.

## Fields every record has

| Field | Type | Holds |
| --- | --- | --- |
| `provider` | `string` | The adapter that produced the record, for example `instantly`. |
| `workspaceId` | `string` | Your label for the credential it came from. |
| `sourceId` | `string` | The vendor's own id, always a string. |
| `ref` | `string` | `provider:workspaceId:sourceId`. Unique across vendors and clients. |
| `schemaVersion` | `1` | `SCHEMA_VERSION`. Bumped only for a breaking change to these shapes. |
| `raw` | JSON | The vendor's original payload for the record. `null` on the in-memory adapter. |

`MetricRow` is the exception: it has `provider`, `workspaceId` and `schemaVersion`, and a `scopeRef` in place of its own `ref`.

`raw` is the vendor's data unmapped, so it holds whatever personal data the vendor sent. The [redact](/docs/plugins/redact) plugin removes it.

- **A ref names one record on one credential.** Two clients on the same vendor, or one client on two vendors, can never be confused, because the workspace label and the provider are in the ref.
- **Wherever the SDK takes an id, it takes a ref.** On an instance with one adapter both work. A ref from another workspace is refused with `Invalid`.
- **On a combined instance, use the ref.** A bare id cannot say which adapter it belongs to. See [troubleshooting](/docs/troubleshooting#a-bare-id-on-a-combined-instance).
- **Fields that point at another record hold its ref**, not its id: `campaignRef`, `leadRef`, `senderRef`, `campaignRefs`, `scopeRef`.
- **Store the ref.** It is the key to use in your own database.

`makeRef(provider, workspaceId, sourceId)` builds one. `parseRef(ref)` returns `{ provider, workspaceId, sourceId }`, or `null` for a string that is not a ref. A vendor id may itself contain colons: everything after the second colon is the `sourceId`. A `workspaceId` cannot be empty or contain a colon, and an adapter constructed with one throws `Invalid`.

## Null is not zero

A value the vendor does not report is `null`. It is never `0`, `""` or `false`.

<include meta='title="nulls.ts"'>../../_examples/api-records/nulls.ts</include>

<include lang="text" meta='title="Output"'>
  ../../_examples/api-records/nulls.out.txt
</include>

`bounced: 0` means the vendor counted bounces and found none. `opened: null` means the vendor gave no open count: tracking was off, or its API does not report it. A rate built on a missing count is `null` too. Print "not reported", not a zero, and do not add `null` counts up as zeros. `sumCounts` from `outbound-sdk` adds rows and keeps a count `null` unless at least one row reports it.

Arrays are the exception. `tags`, `issues`, `events` and `campaignRefs` are empty arrays when there is nothing to report, and `custom` is an empty object.

## Sequence

A campaign's steps. Returned by `campaign(id).sequence()` and `campaign(id).subsequences`.

| Field | Type | Holds |
| --- | --- | --- |
| `campaignRef` | `string` | The campaign it belongs to. |
| `kind` | `"main"` or `"subsequence"` | The campaign's own steps, or a follow-up path. |
| `name` | `string` or `null` | A subsequence's name. `null` for the main sequence. |
| `steps` | `SequenceStep[]` |  |

`SequenceStep`:

| Field | Type | Holds |
| --- | --- | --- |
| `index` | integer | The step's position, counted from 0. |
| `action` | `string` | `email`, or a LinkedIn action such as `connection_request`. |
| `delayDays` | number or `null` |  |
| `parentIndex` | integer or `null` | The step that runs before this one. `null` for the first step. |
| `branch` | `string` or `null` | The outcome of the parent's condition that leads here, in the vendor's words, for example `accepted`. `null` on a straight path. |
| `variants` | `SequenceVariant[]` |  |

`SequenceVariant`:

| Field | Type | Holds |
| --- | --- | --- |
| `variantKey` | `string` | Names the variant within its step. |
| `subject` | `string` or `null` | Template text. |
| `body` | `string` or `null` | Template text, never a rendered message. |
| `contentHash` | `string` | A hash of subject and body, so stats can tell old copy from new. |

## SenderHealth

What the vendor knows about a sender's deliverability. Its `sourceId` is the sender's id.

| Field | Type | Holds |
| --- | --- | --- |
| `senderRef` | `string` |  |
| `domain` | `string` or `null` | The mailbox's domain, lowercased. `null` for a LinkedIn seat. |
| `connected` | boolean or `null` | `true` when the vendor can sign in to the mailbox or seat. |
| `dns` | `{ spf, dkim, dmarc, mx }` | Each `true`, `false` or `null`: whether the record is present and valid. |
| `blacklisted` | boolean or `null` | `true` when the domain or address is on a block list the vendor checks. |
| `issues` | `string[]` | Problems in the vendor's own words. |

| `warmup` | `{ sent, received, inbox, spam, score }` or `null` | Warmup traffic over the vendor's reporting window. |

## Lead

| Field | Type | Holds |
| --- | --- | --- |
| `email` | `string` or `null` | Lowercased and trimmed. |
| `linkedinUrl` | `string` or `null` |  |
| `firstName`, `lastName`, `company`, `title` | `string` or `null` |  |
| `progress` | `"active"`, `"paused"`, `"completed"`, `"skipped"`, `"unknown"` | Where the lead is in its sequence, whatever came back from it. `skipped` is a lead the vendor decided never to send to, for example a duplicate or one over a domain limit. |
| `replied`, `bounced`, `unsubscribed` | boolean or `null` | What came back. `null` when the vendor does not say. |
| `status` | `"active"`, `"paused"`, `"completed"`, `"skipped"`, `"replied"`, `"bounced"`, `"unsubscribed"`, `"unknown"` | The headline: `unsubscribed`, `bounced` or `replied` when one of them is known to be true, in that order, and `progress` otherwise. |
| `phone`, `location` | `string` or `null` | As the vendor stores them. |
| `website` | `string` or `null` | The company's website or domain, as the vendor stores it. |
| `companyLinkedinUrl` | `string` or `null` | The company's LinkedIn page. |
| `recipientMailProvider` | `"google"`, `"microsoft"`, `"other"`, `null`, or absent | Who hosts the lead's own mailbox, as the vendor detected it. `null` when the vendor has not detected it or does not say. Every adapter sets it; it may be absent on a lead built or stored before the field existed, which still matches `leadSchema`. |
| `interest` | `string` or `null` | The vendor's own label for how interested the lead is, for example `Meeting Booked`. |
| `interestCategory` | a reply category or `null` | What `interest` means, in the categories a reply uses. `null` when the lead has no label or the vendor does not say what the label means. |
| `campaignRef` | `string` or `null` |  |
| `createdAt` | ISO timestamp or `null` |  |
| `custom` | `Record<string, string>` | The lead's custom fields as the vendor stores them. An adapter's `leadFields` option can name the one that holds a title, phone or profile. |
| `tags` | `string[]` |  |
| `engagement` | `LeadEngagement` or `null` | `null` when the vendor reports no per-lead counts on this read. |

`LeadEngagement`, what a lead did with the campaign's messages as the vendor counts it:

| Field | Type | Holds |
| --- | --- | --- |
| `opens`, `clicks`, `replies` | count or `null` |  |
| `lastContactedAt`, `lastOpenedAt`, `lastRepliedAt` | ISO timestamp or `null` |  |
| `stepIndex` | integer or `null` | The last step sent to the lead, counted from 0. |
| `repliedStepIndex` | integer or `null` | The step the lead replied to, counted from 0. |

A lead is a person in one campaign. The same person in two campaigns is two `Lead` records. The [identity](/docs/plugins/identity) plugin links them without merging them.

## Message

One message sent or received.

| Field | Type | Holds |
| --- | --- | --- |
| `direction` | `"out"` or `"in"` |  |
| `channel` | `"email"` or `"linkedin"` |  |
| `sentAt` | ISO timestamp or `null` |  |
| `subject` | `string` or `null` |  |
| `bodyText` | `string` or `null` | Plain text with quoted history removed. `null` unless the call asked for bodies and the vendor returned one. |
| `bodyHtml` | `string` or `null` | The same rule. |
| `campaignRef`, `leadRef`, `senderRef` | `string` or `null` |  |
| `threadId` | `string` or `null` | Pass it to `outbound.thread(id)`. |
| `url` | URL, `null`, or absent | Opens the conversation in the vendor's app, built only from a scheme the vendor documents or that was checked live. Instantly links to the thread in its Unibox; HeyReach, Smartlead and EmailBison document no such link, so it is `null`, and their field coverage says so. |
| `stepIndex` | integer or `null` | The sequence step that sent it. |
| `variantKey` | `string` or `null` | The variant that sent it. |
| `isAuto`, `isAutoSource` | as on a `Reply`, or absent | On a received message, where the adapter can tell: Instantly and the memory adapter. |

## Reply

A received message with a category. A `Reply` is one message, not one person: a lead who writes twice in a thread is two replies. To count people, count distinct `leadRef`s; stats count people in `replied` and messages in `repliedTotal`. It has every `Message` field, `direction` is always `"in"`, and it adds:

| Field | Type | Holds |
| --- | --- | --- |
| `category` | `"positive"`, `"negative"`, `"neutral"`, `"ooo"`, `"bounce"`, `"unsubscribe"`, `"unknown"` |  |
| `categorySource` | `"vendor"`, `"lead"`, `"rule"` or `null` | Who decided the category: `vendor` when the vendor labelled this reply, `lead` when it is the vendor's label for the lead who sent it, `rule` for a fixed rule. `null` when it is `unknown`. Never a model. |
| `isAuto` | boolean or `null` | `true` for an auto-reply, `null` when neither the vendor nor a fixed rule says. |
| `isAutoSource` | `"vendor"`, `"rule"`, `null`, or absent | Who decided `isAuto`: `vendor` for the vendor's own flag, `rule` for a fixed rule on the sender's address, the subject, a canned phrase, or a reply within a minute of the send it answers. Never a model. |
| `leftCompany` | boolean, `null`, or absent | `true` when the reply says the person left the company or the contact changed, for example "your contact with Acme has changed". |
| `unread` | boolean or `null` | `true` while the reply, or the thread it is in, is unread in the vendor's inbox. |

## MetricRow

One row of counts. Every count is a number or `null`. Its fields are listed on the [stats](/docs/api/stats#the-counts) page.

## CampaignProgress

How far a campaign's leads have got, as counts of leads. Stats count messages and replies; this counts people. Its `sourceId` is the campaign's id.

| Field | Type | Holds |
| --- | --- | --- |
| `campaignRef` | `string` |  |
| `leads` | count or `null` | Every lead in the campaign. |
| `notStarted` | count or `null` | Leads still waiting for their first step. |
| `inProgress` | count or `null` | Leads who have had a step and have more to come. |
| `completed` | count or `null` | Leads who reached the end of the sequence. |
| `stopped` | count or `null` | Leads taken out of the sequence before its end. |
| `failed` | count or `null` | Leads the campaign could not run for. |
| `blocked` | count or `null` | Leads the vendor stopped for a bounce or a block list. |
| `skipped` | count, `null`, or absent | Leads the vendor decided never to send to, for example ones an exclusion rule kept out. Every adapter sets it; it may be absent on progress built or stored before the field existed, which still matches `campaignProgressSchema`. |

Instantly reports `leads` and `completed` only. HeyReach has no `blocked` count and Smartlead no `failed` count. Only HeyReach reports `skipped` (its excluded leads); Smartlead counts a block-listed lead in `blocked`, together with bounces. [`outbound.fields`](/docs/capabilities#field-grades) says so per adapter.

## PlacementTest

An inbox placement test: the vendor sends a campaign's email to seed mailboxes and reports where it landed. This is the test itself. Its results stay [native reads](/docs/native), because Instantly reports them as a row per email and Smartlead as rates, and the SDK reads counts, never rates.

| Field | Type | Holds |
| --- | --- | --- |
| `name` | `string` |  |
| `status` | `"active"`, `"paused"`, `"completed"`, `"unknown"` |  |
| `kind` | `"one_time"`, `"automated"` or `null` | A test run once, or one on a schedule. |
| `campaignRef` | `string` or `null` | The campaign whose email the test sends. |
| `createdAt` | ISO timestamp or `null` |  |
| `nextRunAt` | ISO timestamp or `null` | When an automated test runs next. |
| `startsAt`, `endsAt` | ISO timestamp or `null` | When a scheduled test starts and stops running. |

Instantly gives a test a creation time, a next run and a campaign. Smartlead's list gives its start and end and none of those.

## Schemas

Each record is defined once as a Zod schema and its TypeScript type is inferred from it. The SDK checks every record against its schema before returning it. A record that does not match fails the call with a `Provider` error naming the field, so a malformed record never reaches your code.

The schemas are exported for checking records that come from somewhere else, such as your own database or a queue:

| Schema | Type |
| --- | --- |
| `campaignSchema`, `campaignStatusSchema` | `Campaign`, `CampaignStatus` |
| `sequenceSchema` | `Sequence` |
| `senderSchema`, `senderStatusSchema` | `Sender`, `SenderStatus` |
| `senderHealthSchema` | `SenderHealth` |
| `leadSchema`, `leadStatusSchema` | `Lead`, `LeadStatus` |
| `messageSchema` | `Message` |
| `replySchema`, `replyCategorySchema` | `Reply`, `ReplyCategory` |
| `metricRowSchema`, `metricScopeSchema` | `MetricRow`, `MetricScope` |
| `campaignSettingsSchema` | `CampaignSettings` |
| `leadListSchema` | `LeadList` |
| `tagSchema` | `Tag` |
| `blockEntrySchema` | `BlockEntry` |
| `webhookSubscriptionSchema` | `WebhookSubscription` |
| `workspaceSchema` | `Workspace` |
| `channelSchema`, `evidenceSchema` | `Channel`, `Evidence` |
| `outboundEventSchema`, `eventTypeSchema` | `OutboundEvent`, `EventType`: see [webhook events](/docs/webhooks/events) |

`SequenceStep`, `SequenceVariant`, `LeadEngagement` and `SendingWindow` are exported as types only. `Entity` is the union of every record a list or get call returns.

`SCHEMA_VERSION` is `1`. Every record carries it as `schemaVersion`, so data you stored can say which shape it was written in.
