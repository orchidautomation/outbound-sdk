You want a model to read what prospects wrote back: to summarise objections, or to draft a note for a rep. Two things are in the way. The records carry personal data you may not want in a prompt. And the text was written by a stranger, who can address your model directly.

The SDK does two separate jobs here, and neither is a guarantee:

- **The `redact` plugin masks fields.** Email, name, company, LinkedIn URL, custom fields, subject and body are replaced before a record leaves the instance. It does not look inside text.
- **The tools mark reply text.** Text is left out unless asked for, cut to 500 characters, and wrapped in an object that says it is untrusted. That is a label. It does not stop prompt injection, and a model may ignore it.

The SDK calls no model and does not inspect, classify or clean reply text.

## Before you start

- Node 22 or later.
- The code runs on the in-memory adapter, so it needs no key. Each sample is a file the test suite runs; the output shown is what it printed.
- For real data: an Instantly, Smartlead or HeyReach API key. A read-only key is enough.

- **Without `include_bodies`** a reply is its category, its time and refs. `body` is `null`. A model that only needs to count or sort replies never sees the text.
- **With it**, `body` is `untrusted_content`, `truncated` and `note`. The second reply is an injection attempt, and it comes through word for word. The third is longer than 500 characters, so it is cut and `truncated` is `true`.
- **`category` comes from the vendor**, never from a model. `category_source` says so.
- **The tool returns refs, not addresses.** `lead` is a ref such as `memory:acme:lead_dana`. But the first reply carries a phone number and an address in its text, because the prospect typed them.

## Mask every field: `redact()`

With no options, `redact()` masks every field it knows and replaces each value with `[redacted]`, and an email address or a profile with a token keyed for that instance, so people stay apart. List it first in `plugins` so it is the outermost layer.

What changed:

- **`messages.body` is turned off.** Asking for text while text is being masked is a contradiction, so the request is refused as `Unsupported` before it is made. Nothing comes back as a masked body.
- **`native` is turned off.** A vendor read returns the vendor's payload as sent, which cannot be masked, so `outbound.native` and `outbound.raw` are refused and the `vendor_read` tool is not offered.
- **`raw` is always `null`.** The vendor's payload holds everything the normalized fields came from.
- **Counts, categories and times are untouched.** Campaigns, stats and sequences pass through. A ref is untouched unless the vendor built the id from an email address or a LinkedIn profile URL: that part is masked like the field.
- **A record it does not recognise is refused**, not passed through.

## Keep the text, mask the people: `fields` and `strategy: "hash"`

To let a model read replies, leave `body` out of `fields`. `messages.body` then stays on. `strategy: "hash"` replaces each value with a stable token, `redacted:` and 16 hex characters, so the same address always gives the same token and people can still be counted and joined.

Read the first reply in that output. The lead's `email` field is a token, and the reply text still says "write to dana@example.com". Redaction masks fields. It does not search text for addresses, phone numbers or names. If that text must not reach a model, do not ask for bodies.

A hash is a token, not anonymity. Anyone who can guess an address can hash it and compare.

## What marking does and does not do

<Callout type="warning" title="The note is a convention, not a control">
  `untrusted_content` and its note tell a model how to treat the text. Nothing
  enforces it. A model can still follow an instruction inside a reply.
</Callout>

What limits the damage is what the agent is able to do, not the label:

- Give an agent that reads reply text no tool that sends, edits or exports. Every tool in this SDK reads, so the risk comes from the other tools you add.
- Leave `include_bodies` off for tasks that only need categories and counts.
- Use a read-only vendor key, so that a confused agent holding the key cannot change anything at the vendor.
- Treat what the model writes after reading replies as unreviewed. A reply can aim at the reader of the summary too.

## What it costs in vendor requests

`redact` makes no request of its own. Reading replies costs what the listing costs, and `meta.requests` reports it. On Instantly, a reply whose body the list cut short costs one more read of that email when bodies are asked for, and the email list is limited to 20 requests a minute.

| What happened | What you get | What to do |
| --- | --- | --- |
| Bodies asked for while `body` is masked | `Unsupported`, before any request. From a tool, `ok: false`. | Leave `body` out of `fields` if a model must read text. |
| A vendor read or a raw request with `redact` on | `Unsupported`, before any request. `vendor_read` is not offered. | Use an instance without `redact` for that read, away from the model. |
| A person looked up by address while `redact` masks `email` or `linkedin` | `Unsupported`, before any read. `cross_channel_lead` is not offered. | Look people up on an instance without `redact`. |
| `redact` listed twice | `Invalid` when the instance is created | List it once. |
| A reply has no text | `body` is `null` | Nothing. A missing body is `null`, never an empty string. |

## Limits

- Redaction masks the fields `email`, `name`, `company`, `linkedin`, `custom`, `subject` and `body`. It does not mask a lead's `title`, and it does not look inside any text.
- An id the vendor built from an email address or a LinkedIn profile URL is masked inside `ref`, `sourceId` and every `*Ref` field. On HeyReach a lead's id is its profile URL, so with `redact` on its `ref` holds a token in its place, one per person, and cannot be passed back to `outbound.lead()`. Any other id is left as it is.
- `redact` turns off `outbound.native` and `outbound.raw`. On an instance without `redact`, both return the vendor's payload unmasked: do not hand them to code a model drives.
- Marking text as untrusted does not stop prompt injection.
- Truncation is by character count, 500 by default in the tools. It can cut a word or a sentence in half.
- Categories are the vendor's. The SDK does not classify replies.
