Every Monday an agency writes the same email for each client: what went out, what came back, what changed, what needs doing. `clientReport` computes all of it in one call: this week against the week before, with a test for whether the change is more than chance; the best campaigns; campaigns over a bounce threshold; campaigns about to run out of leads; days that broke from trend; and a list of actions. It calls no AI model. Every number is a count, a rate or a textbook test.

This guide wraps that call in one function that returns the report as text, runs it for every client behind one instance, and shows what happens when it cannot answer.

## Before you start

- Node 22 or later.
- The code below runs on the in-memory adapter, so it needs no vendor key. Each sample on this page is a file in the repository that the test suite runs; the output shown is what it printed.
- For real data: an Instantly, Smartlead or HeyReach API key. A read-only key is enough. No method of the SDK writes to a vendor.

## Write the report

`outbound.insights.clientReport` takes the length of the period in days and returns `data` and `meta`. The function below formats `data` and passes on anything `meta` says about the answer.

<include meta='title="report.ts"'>
  ../_examples/weekly-client-report/report.ts
</include>

Three things in it are worth copying:

- **A count can be `null`.** A vendor that does not report a number gets `null`, never `0`, and a rate built on it is `null` too. Print "not reported", not a zero.
- **`data.totals.finding` is a sentence.** It already says whether the reply rate moved by more than chance, from a two-proportion test at `alpha` (default 0.05).
- **`meta.complete` and `meta.notes` travel with the report.** When a cap stopped a read early, the report covers part of the data and a note says which part.

"The last 7 days" means seven complete UTC days ending yesterday, so a half-finished today cannot read as a drop.

## Point it at your vendor

Swap the adapter. Nothing else changes.

<include meta='title="outbound.ts"'>
  ../_examples/weekly-client-report/production.ts
</include>

`maxRequests` caps what one call may spend. On a real vendor the report costs two stats requests per campaign, and for each active campaign three more plus a read of its leads (up to `max_leads_per_campaign`, default 500). The default `max_campaigns` is 25. If the cap is reached the call fails with `RateLimited` instead of spending your vendor quota; raise `maxRequests` or lower `max_campaigns`.

## One report per client

Give each client's key its own adapter and a `workspaceId` that is your label for the client. `outbound.workspace(id)` is the same instance scoped to that client, with the same plugins, so the function above runs unchanged. A client on two tools keeps one label on both adapters, and its scope covers both.

## When it cannot answer

</include>

<include lang="text" meta='title="Output"'>
  ../_examples/weekly-client-report/failures.out.txt

| What happened | What you get | What to do |
| --- | --- | --- |
| An input the insight does not take | `Invalid`, naming the key and listing the inputs | Fix the key. An unknown filter is never dropped silently. |
| A cap stopped a read | `meta.complete` is `false` and a note says why | Raise the cap, or send the report with the note. |
| Input out of range | `Invalid`, before any request | Fix the value. |
| The adapter cannot read campaign stats | `Unsupported`, before any request | Use an adapter that declares `stats.campaign`. |
| A rejected key | `Unauthorized`. It is not retried. | Check the key and its scope. |
| The vendor is rate limiting | Waited out and retried for you. `RateLimited` only once `deadline` or `maxRequests` is passed. | Raise the budget, or run the report later. |

## Limits

- The report is per instance or per workspace. There is no filter by campaign tag on `clientReport`; use `tagRollup` to group results by tag.
- Anomalies need at least five days of history before the period (`min_baseline_points`).
- "Leads left" reads up to `max_leads_per_campaign` leads per active campaign. Past that, the report says it is incomplete.
- The numbers are only as good as the vendor's. On an `unverified` adapter, check a report against the vendor's own dashboard before sending it to a client.
